GOAL OF THE PROJECT: make the PS3 slim's ps2_netemu.self read an inserted PS2 disc
straight from the optical drive. The "firmware route" lets the PS2_NE_LPAR netemu
partition reach the drive via live LV1 RAM patches (Components A/B) plus netemu SELF
patches (Components C/D). Read docs/FIRMWARE_ROUTE_PLAN.md in full first; the latest
section (CONSOLE RESULT: bus-99 + A probe) is the newest proven fact.

PROVEN ON CONSOLE 2026-11-26 (just now): with Component A (sysmgr_ss ability bit)
applied, a bare `li r11,170; sc 1` (lv1_open_device) from the netemu partition is
dispatched correctly and returns the true LV1 value (-17 for a nonexistent bus=99),
WITHOUT powering the console off. So the hypercall mechanism is FINE once A authorizes
-- no PHAT-style LPAR-state-switch wrapper is needed. The remaining blocker for the
REAL open(4,2,0) is the optical DEVICE CLAIM: the drive asserts IRQ 9/10, the netemu
guest kernel has no handler, so the unsolicited interrupt vectors to the guest panic
handler -> lv1_panic -> Syscon power-off. That is Component C.
