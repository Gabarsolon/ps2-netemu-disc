## Context (all PROVEN unless marked)
- ps2_netemu runs as an isolated LV1 guest (PS2_NE_LPAR). During PS2 mode LV2/Cobra are gone; only HDD + hypercalls are reachable.
- CONSOLE-PROVEN earlier: lv1_open_device(4,2,0) (optical ROM node bus 4 dev 2) from the netemu partition INSTANTLY POWERS OFF the console (P1b). INFERRED cause: (1) PS2_NE_LPAR leaves the BD PCI bridge unpowered (sysmgr_ss vtable +0xc0 stub), (2) netemu has no optical IRQ (9/10) handler, so an unsolicited drive interrupt hits the guest panic vector at 0xf58 (li r3,0x11f; li r11,0xff; sc 1 = lv1_panic -> power off).
- Two LV1 RAM patches (A: keep optical ability bit; B: make +0xc0 power the bridge via 0x8001decc) are applied EXTERNALLY by the operator before launch (tools/patch_sysmgr_optical.py). You do NOT apply them; assume they are active at test time.
- CONSOLE-PROVEN owned buffer (experiments/netemu_owned_control): after startup the probe owns a fresh 8192-byte block; data region EA 0x80023500 / LPAR 0x3b23500. Use the owned_control build/validate/snapshot pipeline as the base.
- The netemu issues LV1 hypercalls via the `sc 1` instruction (20 sites exist in the decrypted ELF local_only/stock.elf). LV1 ABI: hypercall number in r11, args r3..r10, return in r3 (negative = error).
