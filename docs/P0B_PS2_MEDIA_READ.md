# P0B: why PS2 media reads fail, and candidate unlocks

**Verdict — PROVEN (owner logs):** the CECH-25xx/308R can identify this PS2 DVD and expose its directory, but the probe's ordinary LV2 sector reads fail with **ENXIO**, and its file-data read fails with **EIO**. **INFERRED:** a storage-access/authentication-state restriction is a stronger working explanation than an inability to handle DVDs; public manager code applies LV2/LV1 storage patches and resets/authenticates the drive before ordinary reads. Cobra also has a direct LV1 read path using region 0/flag `0x2`. Its intentional GET CONFIGURATION zero-fill explains the misleading profile. **UNKNOWN:** which of these steps is necessary/sufficient on this exact firmware/drive, the precise rejecting layer, and whether an unlock survives entry into netemu. **No verified universal unlock sequence was found.** Authentication, patches and fake events were not implemented; only append-only probe logging was built. A netemu LV1 caller bypasses LV2 hooks, but does not thereby bypass LV1/device policy.

## 1. Exact error codes and the policy question

| Label / confidence | Code | Exact name | Meaning and limits |
|---|---|---|---|
| **PROVEN (local SDK), high** | `0x8001002F` / signed `-2147418065` | `ENXIO` | No such device or address; wiki wording is “No such device or IO.” Does not mean the drive handle necessarily failed to open. |
| **PROVEN (local SDK), high** | `0x8001002B` / signed `-2147418069` | `EIO` | Input/output error. The wiki's mount-failure wording is an example, not an exclusive definition; this file was already opened. |
| **PROVEN (local SDK), high** | `0x80010009` | `EPERM` | Operation not permitted. |
| **PROVEN (local SDK), high** | `0x80010029` | `EACCES` | Permission denied/access violation. Distinct from `...2F`. |

**PROVEN (local headers):** PS3DK v0.26.0 `ppu/include/sys/return_code.h` is a compatibility shim including `errno.h`, not a full numeric table. The definitions are in `ppu/powerpc64-ps3-elf/include/sys/_lv2_errno.h`, lines 28/90/94/102. Example: `#define ENXIO (-2147418065) /* 0x8001002F */`. The SDK was read only.

**INFERRED (independent public cross-check):** PSL1GHT `master`, [ppu/librt/lv2errno.c](https://raw.githubusercontent.com/ps3dev/PSL1GHT/master/ppu/librt/lv2errno.c), lines 14–17, maps the two values to EIO/ENXIO and describes the latter as “No such device or address”. Its EPERM/EACCES cases are separate. The requested upstream `ppu/include/sys/return_code.h` could not be fetched; it is not cited as an inspected error table. This libc conversion is **LV2 → errno**, not **LV1 → LV2**.

**CLAIMED (wiki, agreeing with the local definitions):** [Error Codes, Generic errors](https://www.psdevwiki.com/ps3/Error_Codes#Generic_errors) lists `ENXIO | 0x8001002F` and `EIO | 0x8001002B`. The separately requested [LV2 Error Codes URL](https://www.psdevwiki.com/ps3/LV2_Error_Codes) was inaccessible; no additional table is invented from it.

**INFERRED (public ABI):** Linux defines `LV1_NO_PRIVILEGE=-3`, `LV1_DENIED_BY_POLICY=-4`, `LV1_ACCESS_VIOLATION=-5`. These are a different namespace from `0x8001xxxx`; see [Linux ps3.h at commit 0c59ae1290741854b6cf597ef05bfa9bc811389f](https://code.googlesource.com/linux/torvalds/linux/+/0c59ae1290741854b6cf597ef05bfa9bc811389f/arch/powerpc/include/asm/ps3.h), enum `lv1_result`, quote: `LV1_DENIED_BY_POLICY = -4`.

**UNKNOWN (important gap):** no inspected primary source established the **4.93 LV2 storage error-translation table** for those LV1 errors. EPERM/EACCES are the named LV2 permission errors, but claiming that LV1 `-4` invariably becomes either one would be unsupported. A storage layer can collapse failures to ENXIO/EIO; the observed codes neither prove nor rule out an underlying policy denial. [RPCS3 sys_storage.cpp, master](https://raw.githubusercontent.com/RPCS3/rpcs3/master/rpcs3/Emu/Cell/lv2/sys_storage.cpp) is a partial emulator implementation (`sys_storage.todo`), not evidence for Sony's translation. The exact lower error requires instrumentation or matched LV2 static analysis; it was not recovered here.

## 2. What the actual manager/payload sources do

### IRISMAN: patches plus a firmware-dependent drive setup

**INFERRED:** [IRISMAN master, source/payload480/payload_480.c](https://raw.githubusercontent.com/aldostools/IRISMAN/master/source/payload480/payload_480.c), `lv2_patch_storage_480`, lines 315–356, patches both layers. Quote: `// LV2 enable syscall storage`. It changes a kernel instruction at `0x80000000002ECAA0`, then four LV1 sites (`0x16FA60`, `0x16FA84`, `0x16FAFC`, `0x16FB04`) using LV1 peek/poke; `lv2_unpatch_storage_480` restores saved words. These are historical firmware-specific addresses, **not a proposed 4.93 patch**. The bit changes alone do not establish the full checked policy's semantics.

**INFERRED:** [IRISMAN master, source/main.c](https://raw.githubusercontent.com/aldostools/IRISMAN/master/source/main.c), lines 2388–2394 and `DiscInsertCallback` 1658–1669, applies the storage patch where available and not using Mamba, and selects `Reset1_BDVD` below `0x421C`, otherwise `Reset2_BDVD`, conditional on physical-drive mode and a storage-patch function. It also performs setup when the initial directory open fails. Quote: `if(firmware < 0x421C)`. Cobra/Mamba defaults to discless mode (line 2489), so these calls are conditional, not guaranteed on every manager start. A copied ABI header omits this initialization/context.

**INFERRED:** [IRISMAN master, source/psx.c](https://raw.githubusercontent.com/aldostools/IRISMAN/master/source/psx.c), `Reset1_BDVD`/`Reset2_BDVD`, lines 2295–2358:

| Label | Path | Source sequence (describe only; not implemented) |
|---|---|---|
| **INFERRED** | Older setup | Reset BD; on success authenticate BD; then control function `0x3F`. |
| **INFERRED** | Newer setup | Reset BD; on success control function `0x43`; then control function `0x3F`. |
| **INFERRED** | Data readers | `get_psx_region_cd` uses ordinary `sys_storage_read` at sectors 4/16. `read_raw_sector_bdvd` uses ATAPI READ CD `0xBE`, DMA protocol 3, inbound, selected 2352/2368-byte layout; the CD copier also reads TOC. |

**INFERRED:** the old loops retry busy up to 500,000 times; raw-CD retry loops are not timed. Quote: `// new method`. These loops are not suitable probe timeout policies. This file is chiefly PS1/CD handling; it does not prove an identical PS2 DVD ripping caller.

**INFERRED (exact ABI):** [IRISMAN master, include/storage.h](https://raw.githubusercontent.com/aldostools/IRISMAN/master/include/storage.h), lines 183–213, maps reset to **syscall 864 `(0x5004, 0x29)`**, drive authentication to **864 `(0x5004, 0x46)`**, and control to **864 `(0x5007, pointer-to-three-u64s)`**, first word the function. Quote: `In order to execute syscall 864 the access rights of LV2 need to be patched`. The helper only initializes that first word; do not treat it as a fully specified safe packet template. The probe has none of these adapters. Its ordinary read flags are zero, matching this header's read wrapper; blindly changing them to LV1 flag `2` is not an established ABI equivalence.

**CLAIMED (reverse-engineering notes):** [PSDevWiki Storage Manager](https://www.psdevwiki.com/ps3/Storage_Manager#0x5004_-_Authenticate_BD_Drive) calls `0x29` “Reset BD Drive + cleans key”, `0x46` drive authentication, `0x52` PS2 insert policy checking; `0x5007` controls include `0x43` disc change and `0x3F` authentication/profile work. It locates the service in LPAR1 and describes an ATAPI path to `/dev/rbd0`. It also records authentication/reset on partition load/unload and PS2EMU transitions. **INFERRED:** these are state-changing security services reaching below LV2; they are not mere query names. **UNKNOWN:** their precise packet exchange and persistent state on 308R/7028, and whether the transition into netemu reinitializes an otherwise useful state. `0x5005` being named PS2 authentication does not establish that it should be called to rip a disc.

### webMAN MOD: authentication, copying, and two different PS2 mounts

**INFERRED:** [webMAN-MOD master, cobra/cobra.c](https://raw.githubusercontent.com/aldostools/webMAN-MOD/master/cobra/cobra.c), `cobra_disc_auth` 691–713, queries the real type and calls **`sys_ss_disc_auth(0x5004, 0x29);`** for non-PS3 media. PS3 media takes `0x5007` with a buffer. The function returns 0 without propagating the authentication call result: its return value is not sufficient evidence of an unlock. Fake eject emits events **4,8**; fake insert **7,3**. They change LV2's media lifecycle; they are not a sector read or a physical eject command.

**INFERRED:** [webMAN-MOD master, include/mount/mount.h](https://raw.githubusercontent.com/aldostools/webMAN-MOD/master/include/mount/mount.h), `do_umount_iso` 930–950, ejects/unmounts an image, reinserts the real disc, waits for `/dev_bdvd`, then calls `cobra_disc_auth()`. Quote: `// If there is a real disc in the system, issue an insert event`. **UNKNOWN:** that sequence alone fixes this failure; it can also make earlier mount history relevant.

**INFERRED:** [webMAN-MOD master, include/file/file_copy.h](https://raw.githubusercontent.com/aldostools/webMAN-MOD/master/include/file/file_copy.h), `file_copy` 184–185/218–253 and `recursive_folder_copy` 373–376, invokes `sysLv2FsBdDecrypt()` for `/dev_bdvd`, then opens read-only and uses `cellFsReadWithOffset`. Quote: `sysLv2FsBdDecrypt(); // decrypt dev_bdvd files`. **UNKNOWN:** the helper's full implementation/4.93 behavior and applicability to PS2 were not established; its name is not proof that a PS2 disc requires PS3 decryption. This copy path is also not purely read-only preparation. No standalone PS2 physical-disc sector ripper was identified in the inspected webMAN paths.

**INFERRED:** [webMAN-MOD master, include/mount/ps2_disc.h](https://github.com/aldostools/webMAN-MOD/blob/master/include/mount/ps2_disc.h), `mount_ps2disc`, mounts ISO9660 at `/dev_ps2disc`, unmounts the active image, and maps **a supplied directory** onto that path between fake events. ### Cobra: low-level reads, synthetic profile, and launch patches

**INFERRED:** [Joonie86/COBRA-7.3 master, 486/LITE/stage2/storage_ext.c](https://raw.githubusercontent.com/Joonie86/COBRA-7.3/master/486/LITE/stage2/storage_ext.c), `process_read_disc_cmd` 555–589, opens an LV1 storage wrapper and reads **region 0, flags `0x2`**, then closes. Quote: `lv1_stor_wrapper_read(&var, 0, cmd->start_sector, cmd->sector_count, 0x2, cmd->buf);`. Comments motivate this by LV2 ready-event timing and access to the real disc with an image mounted. `is_psx` uses this to inspect PVD/SYSTEM.CNF. `patch_ps2emu_entry` skips software netemu and patches LV1 for recorded-media support in the other emulators. **UNKNOWN:** this is sufficient for an original PS2 DVD on 308R, or flag 2 works unmodified in netemu. Internal wrapper device IDs are not proven portable partition IDs.

**INFERRED:** [Evilnat Cobra 8.5, main, 4.93 CEX storage_ext.c](https://raw.githubusercontent.com/xXEvilnatXx/Cobra-PS3/main/8.5/4.93/CEX/SRC/stage2/storage_ext.c), `process_cmd` 2281–2289, deliberately returns a zeroed GET CONFIGURATION response for effective PSX CD / PS2 CD / PS2 DVD. Quote: `// Region bypass on original psx/ps2 disc`. `process_read_disc_cmd` still uses region 0/flag 2. This strongly explains the owner's profile `0000`; **UNKNOWN:** the actual installed hook bytes were not inspected. A zeroed whole buffer is not a trustworthy drive-reported “no medium” response, especially alongside valid capacity/structure. Its zero length also prevents treating it as a complete valid feature list. No evidence shows this synthetic response itself causes the failed read.

**INFERRED:** [Evilnat Cobra 8.5, main, 4.93 PEX storage_ext.c](https://raw.githubusercontent.com/xXEvilnatXx/Cobra-PS3/main/8.5/4.93/EVILNAT/PEX/SRC/stage2/storage_ext.c), `emu_storage_read` 1576–1605, substitutes image data only while image emulation is active; otherwise it passes through. `emu_disc_auth` has VSH-specific reset/reinsert handling. The software-emulator launch path still explicitly rejects a real PS2 disc: quote `Sorry, no optical disc support in ps2_netemu`. Thus Cobra support for detecting/ripping real media is not an implemented netemu optical backend. **UNKNOWN:** which matching CEX/PEX build the owner's installed Cobra contains.

**CLAIMED (old HV research, not a 4.93 guarantee):** [Hypervisor Reverse Engineering, storage region ACLs](https://www.psdevwiki.com/ps3/Hypervisor_Reverse_Engineering) says `If (flags & 0x100000002) != 0` skips an access-right check and reports a successful flag-2 experiment on HV 3.41. It separately describes command filtering and per-region authority. **INFERRED:** this makes Cobra's flag choice a concrete access-control candidate, not evidence of a drive firmware unlock. It is not safe to equate ACL bypass with authentication, physical readability, or permission from netemu's different authority context.

### Drive/media differences and the directory puzzle

**INFERRED:** the located firmware split is explicit in IRISMAN; the recorded-media patches additionally warn about model-dependent addresses. **UNKNOWN:** no inspected source establishes a 308R/7028-specific unlock, a fat-versus-slim command matrix, or identical behavior for PS2 CD and DVD. The original PS2 DVD already has a 2048-byte capacity; CD raw reads/TOC and 2352-byte layout are distinct. The probe's successful PS3 path reduces the likelihood of a general pointer/ABI error, but does not prove the DVD laser/media is faultless.

**INFERRED:** cached ISO9660 directory records can serve names, sizes, stat and open without fetching the target executable's data sectors. A privileged mount-time path or changed authentication state after mounting could also produce this split. **UNKNOWN:** whether metadata here came from an LV2 cache, a privileged filesystem read, an earlier mode, or a mapped image. No inspected source establishes a dedicated Cobra **physical PS2 directory cache**; its located sector caches are for emulated images. Neither a working directory listing nor an opened file proves current payload-sector access. Conversely it is evidence against calling the entire disc “unrecognized”.

## 3. Consequences for netemu and Linux

**INFERRED (architecture, not a successful read):** a netemu request forwarded to LV1 245 or 248 never goes through the previous GameOS `sys_storage_read`/Cobra LV2 hooks. An **LV2-only** restriction would therefore be absent. An LV1 region/authority restriction, a command filter, or drive authentication state can still refuse it. Drive setup is not proven to persist across partition transition; the Storage Manager notes above explicitly describe transition-time reset/authentication. **UNKNOWN:** optical device visibility, assignment, allowed regions/commands and media state in this owner's netemu partition. The LV2 ENXIO is neither a proof of netemu failure nor a reason to promise direct-LV1 success.

**INFERRED:** [Linux master, drivers/scsi/ps3rom.c](https://raw.githubusercontent.com/torvalds/linux/master/drivers/scsi/ps3rom.c), `ps3rom_queuecommand_lck`/`ps3rom_read_request` 147–215, routes READ(10) to **LV1 245**, repository region, flags **0**. Other SCSI packets use **LV1 248, command 1**, with a 12-byte packet and valid LPAR/DMA buffers. Its ATAPI path explicitly handles `LV1_DENIED_BY_POLICY` by returning `DID_ERROR << 16`; quote: `ATAPI command 0x%02x denied by policy`. There is no PS1/PS2-specific authentication or media-type unlock branch in this file. The completion path separately decodes packed check-condition status; submission rc, tag and completion status must all be captured in a future guest probe. This is direct proof that a guest can encounter LV1 policy even without LV2, not a record of PS2 behavior on a slim.

**INFERRED:** [Linux master, drivers/ps3/ps3stor_lib.c](https://raw.githubusercontent.com/torvalds/linux/master/drivers/ps3/ps3stor_lib.c), `ps3stor_probe_access`, quote: `/* special case: CD-ROM is assumed always accessible */`. It skips the region-read accessibility test for ROM; this is an initialization assumption, not proof that every inserted medium is readable. Setup creates device/event/DMA resources. Synchronous helpers wait for completion without a deadline; they must not be copied unchanged into netemu experiments.

**UNKNOWN (report search):** no usable primary bug report or reproducible **real slim + PS2/PS1 disc + Linux + identified firmware + LV1 result** was located. The Linux denial-handling branch is not such a report. Ordinary Linux operation/BD access reports do not establish PS2 access. Any assertion that OtherOS always reads PS2 discs, or that netemu inherits OtherOS's access policy, remains **CLAIMED at best**. No Linux installation is proposed for this investigation.

## 4. Ranked next console experiments — owner decision, none executed

**INFERRED (proposed order):** first decide whether to allow an **existing manager's state-changing setup**, as opposed to changing this probe. The following order isolates what persists after the manager exits and avoids a whole-disc rip. Do not launch the physical PS2 disc icon: the inspected Cobra launch branch can call fatal.

1. **UNKNOWN → test, highest value:** with this same PS2 DVD and no virtual image mounted, run the v2 read-only probe once; exit. Start existing multiMAN, switch from mmCM into **normal multiMAN mode**, and try opening the tiny `SYSTEM.CNF` in its file/text viewer (55 bytes in this log). Exit to XMB without launching a game, ejecting, mounting an ISO or copying a disc. Run the same probe again. Save the entire cumulative `/dev_hdd0/tmp/ps2disc_probe.log`, manager version/mode and exact viewer result. **INFERRED worst case:** manager changes in-memory patches/mount/authentication state or settings, or hangs the console and needs restart; probe watchdog cannot recover a kernel-wide hang. A manager-only success with subsequent probe failure suggests a nonpersistent/private path or restoration, not a useless result. A second probe success establishes persistent preparation within GameOS, not netemu access.
2. **UNKNOWN → test, isolate the mode:** if the first comparison is useful, repeat from a fresh normal boot using **mmCM**, separately from normal multiMAN. Preserve both logs. **INFERRED worst case:** the same manager/drive state changes or hang; a different setup history otherwise confounds the comparison. This checks the CECH-2101A claim on the actual 308R without beginning a rip.
3. **UNKNOWN → future explicit authorization:** if existing-manager preparation is insufficient or cannot be isolated, design a separate state-changing diagnostic with exact firmware checks, backups/restoration and one step per run. Candidate steps are the **864 `(0x5004,0x29)` reset**, then the reviewed IRISMAN newer `0x5007` control sequence, or a validated LV1 region-0/flag-2 read. Do not mix them in the first trial; capture baseline and every rc plus returned bytes. **INFERRED worst case:** wrong authentication parameters or firmware patch damages runtime state, stops drive access or crashes/powers off; recovery may require reboot. Historical offsets are not safe inputs. **PROVEN (deliverables):** no such diagnostic/patch was added here.
4. **UNKNOWN → later media coverage:** repeat the successful minimal preparation/read method with an original PS2 CD, another original PS2 DVD and, separately, dual-layer DVD if available. Use the appropriate sector/TOC path rather than assuming raw-CD layout. **INFERRED worst case:** unsuccessful seek/read or hang requiring restart; no test writes to the disc are proposed. Do not alter the owner's images.
5. **UNKNOWN → netemu only after review:** follow P0's open-only repository/device probe, then an independently mapped, bounded single-sector read with raw submission/completion diagnostics and fail-open stock behavior. Test baseline flags first; ACL-bypass/security steps require a separate owner decision. **INFERRED worst case:** a bad guest mapping/store/interrupt setup powers off or hangs the console; restoring a patched emulator may be necessary. This is where direct-disc feasibility is proved, not by a successful LV2 manager read.
