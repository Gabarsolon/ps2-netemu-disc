# P0 static analysis

**Verdict — INFERRED plausible; UNKNOWN on the console:** this netemu has the LV1 open/close, repository, DMA, event and storage-read machinery needed to attempt a second device. Its HDD device ID comes from repository enumeration, not a fixed final ID. A physical optical backend is therefore technically plausible, but no evidence here establishes that the CECH-25xx emulator partition is assigned the optical device or may read PS2 media. An important complication is that the exact Cobra read hook hides backend errors by returning the requested length. P0 built a separate LV2 read-only probe; it did not patch netemu, contact the PS3, or execute console code.

Evidence labels follow NETEMU_KNOWLEDGE.md: PROVEN requires a performed check or execution; INFERRED covers static interpretation; CLAIMED covers external assertions; UNKNOWN identifies untested console behavior. Source listings that reproduce Sony code remain in `local_only/analysis/`.

## Reproduction

`python tools/p0_ghidra.py` imports the SHA-256 checked ELF with PowerPC:BE:64:default. Project, JVM temporary files and settings reside in `local_only/ghidra/`; generated listings and decompilations reside in `local_only/analysis/`. One Ghidra job runs at a time.

**PROVEN (PC):** the prepared ELF matched SHA-256 `63f12b7e00959c758f8aedfd23d1b8bc78e8ae7d922048e4765aaaef1dbbc6d3`. Ghidra imported/analyzed it and produced disassembly, references and targeted decompilations. Function descriptors with TOC `0x751280` recover entries missed by automatic analysis. No capstone was used. Decompiler output around `sc` does not reliably model returned registers: arguments and return checks below were checked in the instruction listings. Static control-flow interpretations remain INFERRED.

## LV1 inventory and ABI

**PROVEN (PC decoding):** the 557 opcode matches contain 20 `sc 1` words and 537 `sc 0` words. **INFERRED:** `0x13730` is an opcode template in a table containing other privileged-instruction encodings, not an identified executable callsite. The 19 executable candidates are 15 panic traps, the generic bridge `0xca0`, virtual-UART calls `0x12e10`/`0x134e4`, and device-command call `0x13644`.

**INFERRED:** at `0xc50` the exception bridge strips `0x80000000` from the guest syscall number in r11; `0xc64` bounds it below 256, and `0xc74..0xc84` checks a per-number privilege byte before reaching `sc 1` at `0xca0`. Thus `sc 0` with r11=`0x800000f5` is an LV1 storage read after forwarding. Ordinary guest syscall 7/8 events are a different namespace. An inventory confined to direct `sc 1` would miss the HDD path.

The complete number/wrapper/direct-caller tables are in [P0_HYPERCALLS.md](P0_HYPERCALLS.md), generated by `python tools/p0_hypercall_report.py` from Ghidra evidence. **INFERRED:** 163 constant forwarded sites in 133 wrapper/number groups were reconstructed. Counts are known direct callsite lower bounds; function-descriptor/dispatch-table callers are not claimed as a complete call graph. Local `sc_inventory.json` retains every match and its surrounding disassembly.

**INFERRED, high confidence numeric identifications:** the important Linux names are `open_device`=170/`0xaa`, `close_device`=171/`0xab`, repository read=91/`0x5b`, event-port construction=18/`0x12`, connect device interrupt/event port=197/`0xc5`, DMA allocate/free/map/unmap=174..177, read/write=245/246, device command=248, get async status=249. The public Linux ABI does **not** give separate `lv1_storage_open`/`close` numbers. No constant network/gelic call or storage-check-async-status 254 was identified in this scan; arbitrary/dynamic use is not excluded. [Linux LV1 declarations](https://raw.githubusercontent.com/torvalds/linux/master/arch/powerpc/include/asm/lv1call.h), [wiki HV call reference](https://www.psdevwiki.com/ps3/HV_Syscall_Reference).

## UFS to the actual HDD

**INFERRED:** `raw_read` `0x1ed5cc` is a serialized **file** reader, not an LV1 storage wrapper. It validates one of eight open-file slots, then calls file-block traversal `0x1ec084`. That resolves direct/indirect UFS blocks and clamps a read at the inode file length. Physical byte reads go through `0x1ebb70`, which handles partial 512-byte boundary sectors using scratch at file context `+0x270`. Aligned portions reach `0x1eb780`; it requires byte offset/count divisible by 512 and calls cached HDD reader `0x12d224` for reads (or `0x12d0ac` for writes).

**INFERRED:** `open` `0x1ecc5c` allocates one of eight file slots, parses filesystem superblocks/inodes and walks the supplied path. Its lower `0x1eb770` open adapter simply returns 0; `0x1eb778` close is also a stub. Opening another UFS file therefore does not open another LV1 device. `stat` `0x1ec760` copies inode metadata, including a 64-bit size at output `+0x28`. `0x1ec084` can return zero at EOF, negative errors, or the clamped byte count; lower block errors become `-5`. The eight file slots are not eight outstanding device commands.

**INFERRED:** cache reader `0x12d224` obtains 32-sector (16 KiB) cache blocks via `0x12ce80`; missing sectors invoke `0x12b5fc` with sector count `0x20` and retry budget `0x400`. Cache validity/dirty masks are separate. The lower driver also has write/flush paths; their existence is recorded for analysis only and does not authorize their use in a probe.

### Device selection

**INFERRED, registers/keys checked:** initialization `0x12be04` uses HDD state **`H=0x241c850`** (TOC `-0x6f58`). At `0x12be74..0x12beb0`, key encoder `0x111f6c` constructs `bus[4]` and `id`, then repository helper `0x111eb8` reads the bus ID into `H+8`. The helper issues LV1 91 at `0x111f10` with repository partition argument **1** and returns r4/r5 through two output pointers.

**INFERRED:** enumeration `0x114ea4(4, 0, info, 0, 2)` searches **bus index 4**, starting **device index 0**, filtering **device type 0, port 2**. These are selectors, not final LV1 bus/device IDs. It reads `bus/dev/id`, `type` and `port`; it also gathers PCI, interrupt and register information plus `meddling`, `blk_size`, `n_blocks`, `n_regs`. Actual device ID is `info+8`, saved at `H+0x10` (`0x12bf74..0x12bf80`). The actual bus/device IDs are supplied to `open_device` at `0x12bf8c`, flags 0. A failed lookup can be retried ten times by the initializer; an unrecoverable bus lookup reaches fatal helper `0x111a7c`.

**INFERRED:** native key strings include `bus`=`0x300960`, `dev`=`0x3009f0`, `id`=`0x300388`, `type`=`0x3009f8`, `port`=`0x300a00`, `blk_size`=`0x300a40`, `n_blocks`=`0x300a50`, `n_regs`=`0x300a60`. Keys are packed into registers, so searching only ASCII strings for whole node paths would miss the lookup structure. No boot-parameter-derived final HDD ID appears in this traced path.

**INFERRED from Linux types:** storage **bus type 5**, DISK **device type 0**, ROM **device type 5**, FLASH **device type 14** are separate classifications. Bus **index 4** in netemu is yet another quantity. An LV2 ID such as `0x0101000000000006` is not an established LV1 device ID. [Linux platform types](https://raw.githubusercontent.com/torvalds/linux/master/arch/powerpc/platforms/ps3/platform.h).

### Event, DMA and completion

**INFERRED:** after HDD open, `0x12bfa0` constructs an event receive port, stored at `H+0x18`; `0x12bfd0` connects `(bus_id, dev_id, port, 0)`; `0x12bfec` connects guest interrupt **0x12** to that port. Handler `0x12b320` acknowledges with LV1 27 at `0x12b33c`, gets async status with LV1 249 at `0x12b350`, stores returned tag/status at `H+0x38`/`H+0x40`, and signals guest event **0x2000** at `0x12b36c` only if status retrieval succeeded.

**INFERRED:** initializer requests a **1 MiB** buffer under the `SB_HDD` allocation label (`0x12bff8..0x12c018`), retaining a physical/LPAR-side address at `H+0x20` and CPU-side address at `H+0x28`. LV1 174 at `0x12c03c` allocates a **0x80000-byte** device DMA region with page exponent **12**, flags 0; returned DMA base goes to `H+0x30`. Helper `0x160fc` issues LV1 176 at `0x16134`, mapping size `0x80000`, flags **`0xe000000000000800`**, using that buffer address and DMA base. The exact allocator's internal address-space conversions merit independent validation before reusing it; a generic guest buffer is not automatically valid device DMA.

**INFERRED:** allocator shim `0x19a5c..0x19ab0` bounds the request and tail-calls `0x19900`. That rounds to 1 MiB units, calls memory allocator `0x1622c` with page exponent 20, derives a CPU mapping using an allocation cursor, and calls page-table mapping helper `0x16790`. The DMA setup and CPU mapping are therefore distinct steps; this is not a plain malloc-to-DMA cast. Listing `range_00019800_0001a300.asm` preserves the shim that automatic function grouping initially missed.

**INFERRED:** storage submission `0x12b674` passes `(dev=H.device, region=1, start_sector, sector_count, flags=0, buffer_lpar)` and saves the returned tag at `H+0x48`. The command uses one tag slot. It then waits on guest event 0x2000 (`0x12b70c`) until the handler's tag matches; completion status 0 returns `count << 9`, nonzero returns `-1`. Submission failures retry up to the caller's budget with about 10 ms timebase delay (`0xc2d30` ticks at the briefing's 79.8 MHz), aborting with `-0xb` if the driver's enabled flag clears. **No completion deadline appears:** failure to receive the event or a matching completion can block indefinitely. The retry counter does not bound the successful-submission wait.

**INFERRED:** cleanup `0x12d420` flushes dirty cache, marks the driver disabled and calls DMA unmap/free/device close at `0x12d5e4`, `0x12d5fc`, `0x12d610`. Its singleton state and HDD-specific cache/region assumptions are unsuitable for a second device without separation.

### Whole-chain pseudo-C

**INFERRED reconstruction, not copied source; omitted branches are named rather than silently treated as success:**

```c
init_hdd() {                         // 0x12be04; startup, not per-file open
    H.bus = repo(1, key("bus",4), key("id",0), 0, 0);
    info = enumerate_device(4, 0, TYPE_DISK_0, PORT_2); // 0x114ea4
    H.dev = info.id;                 // actual IDs are repository outputs
    require_success(lv1_open_device(H.bus, H.dev, 0));
    H.port = require_event_port();
    connect_device_event(H.bus, H.dev, H.port, 0);
    connect_guest_irq(0x12, H.port);  // handler 0x12b320
    allocate_driver_buffer("SB_HDD", 0x100000, &H.lpar, &H.cpu);
    H.dma = allocate_device_dma(H.bus, H.dev, 0x80000, 12, 0);
    map_device_dma(H.bus,H.dev,H.lpar,H.dma,0x80000,0xe000000000000800);
    initialize_cache_and_other_hdd_state();
    // Real code has lookup/open/allocation failure branches; not a safe API.
}

hdd_read(buffer_lpar, lba, count, retries) { // 0x12b5fc
    H.completed_tag = INVALID;
    do {
        mask_interrupts();
        rc = lv1_storage_read(H.dev, 1, lba, count, 0, buffer_lpar, &tag);
        if (rc == 0) H.expected_tag = tag;
        restore_interrupts();
        if (rc == 0) {
            do { wait_guest_event(0x2000); }
            while (H.completed_tag != H.expected_tag); // no deadline
            return H.status == 0 ? count * 512 : -1;
        }
        if (--retries == 0) return rc;
        delay_and_check_enabled();   // may return -0xb
    } while (true);
}
irq_0x12() {                        // 0x12b320
    lv1_end_of_interrupt(irq);
    rc = lv1_storage_get_async_status(H.dev, &tag, &status);
    if (rc == 0) { H.completed_tag=tag; H.status=status; signal(0x2000); }
}

ufs_open(ignored_device, path) {     // 0x1ecc5c
    lock_global_ufs(); allocate_one_of_eight_slots();
    probe_superblocks(); walk_inodes_and_path(); unlock_and_return_fd_or_error();
}
ufs_stat(fd, st) {                  // 0x1ec760
    lock_global_ufs(); validate_fd(); copy_inode_metadata(st); // size at +0x28
    unlock(); return status;
}
raw_read(fd, off, dst, bytes) {      // 0x1ed5cc
    lock_global_ufs(); validate_fd();
    // 0x1ec084 walks inode direct/indirect blocks, clamps at EOF.
    // 0x1ebb70 copies boundary fragments through 512-byte scratch.
    // 0x1eb780 converts aligned byte offsets/counts to 512-byte sectors.
    // 0x12d224/0x12ce80 fill 32-sector cache blocks via hdd_read().
    rc = read_file_blocks(fd,off,dst,bytes);
    unlock(); return rc;            // bytes, zero at EOF, or negative
}
```

## Optical references and a misleading second reader

**INFERRED:** Ghidra's matching string inventory is `local_only/analysis/strings.json` (212 defined strings, including embedded guest strings). Native references include `/game/%s/USRDIR/DISC.IDX` at `0x300ba0`, `/game/%s/USRDIR/ISO.BIN.ENC` at `0x3015e8`, `SB_HDD` at `0x300c70`, `SB_IOP_HDD` at `0x300c78`, `SB_CDVD` at `0x301638`. Many `cdvd_driver`, media-error and dual-layer strings at `0x953bc0..0xb009a8` belong to embedded PS2 modules and do not establish a native optical driver. No native `/dev_bdvd`/ATAPI/SCSI command builder was identified; absence of a discovered reference is not proof that no hidden path exists.

**PROVEN (PC byte search):** case-insensitive whole-ELF literal counts are `dev_bdvd=0`, `bdvd=0`, `atapi=0`, `scsi=0`, `ufs=1`, `storage=2`, `iso=3`, `media=32`, `cdvd=109`. This searches stored bytes only, not dynamically constructed strings. Addresses/references for defined strings are retained locally.

**INFERRED:** `0x13644` is LV1 device command **248**, but r4 is **0x88**, r6 is 8, and buffers come from the native crypto state. It is the dedicated ENCDEC/decryption path reached through guest syscall 18, not an ATAPI packet. It must not be repurposed as a read-only optical probe. The numeric syscall template word `0x13730` likewise does not demonstrate another drive call.

**INFERRED:** the separate `0x1e7928`/`0x1e77c8` reader is **flash**, not optical: `0x1e7950` calls repository scanner `0x1e9ba0` with bus type **5** and device type **14**. Scanner reads `bus/type`, `id`, `num_dev`, then device `type` and PCI nodes. Helpers `0x1ea240`/`0x1ea1e8` resolve the actual IDs, used by open `0x1e79a4`. Reads at `0x1e7850` use region 2, flags 4, a 512-byte unit and repeated async-status polling `0x1e787c`. A 100-attempt submission counter does not bound the inner completion-poll loop. This is evidence of another storage client, not a ready-made optical backend.

## CDVD image layer

Detailed addresses and evidence are in [P0_CDVD_NOTES.md](P0_CDVD_NOTES.md). **INFERRED, instruction checked:**

- Open `0x3960` dispatches to `0x40bc`; calls are `0x135f70` and `0x136ff4`. Stat `0x39b0` dispatches to `0x3ff8`; call `0x135fac`. Read `0x3cfc` is an indirect call inside `0x3bdc`; its function descriptor points to `0x1ed5cc`.
- Stat size becomes CDVD context `+0x58`. Cobra synthesizes a 16 KiB LIMG header, media 1=DVD/2=CD, sector count=size/2048 or raw-CD size/2352. Native setup maps media to 0x14/0x12. User data is 2048 bytes; stored stride and CD 0x18 skip are separate.
- DVD setup reads LBA 16, uses PVD big-endian volume-space count at `+0x54`, clamps to total sectors and stores first-volume extent. TOC generator `0x135ccc` emits DVD dual-layer information when that extent is smaller than total, or cached CD track records. Media/TOC are modeled from image metadata, not queried from a physical drive.
- Media presence is modeled: singleton context `0x2458448` has open flag bit 0; close `0x135ee8` clears it and the media word, successful open `0x136ecc` sets it, and query `0x136414` returns zero when absent or the media-type byte when present. This establishes an emulated image present/absent state; exact tray-open/closed command semantics remain UNKNOWN.
- `0x1364f4` checks guest buffer extent/base, then either sends one bulk byte read (`lba*stride`, `count*stride`) or converts sector layout one sector at a time. These guest-memory bounds do not establish suitability for LV1 DMA.
- Dispatcher `0x1359d4` calls `0x1377c4` or direct UFS `0x1ed5cc` through descriptors. The shared native worker `0x12c110` waits for CDVD request event `0x4000000000`, calls the dispatcher at `0x12c4f4`, and signals completion `0x8000000000` at `0x12c508`. The CDVD caller waits; one request occupies the context slot. Scheduling tolerance to drive seeks remains UNKNOWN.
- **Critical correction to the briefing:** `0x3d04` overwrites the backend return with the requested length. Negative/short raw reads are hidden on this Cobra path. Native container/setup code has short-read/error checks, some fatal, but they cannot detect a backend error after forced success. No physical-drive retry/deadline policy was identified. Guest-visible behavior on an actual failure, and complete tray-state transition semantics, remain UNKNOWN.

**INFERRED:** direct calls to `0x1ed5cc` recovered by Ghidra occur at `0x11b058`, `0x11b168`, `0x11b18c`, `0x11cb54`, `0x12a9bc`, `0x12c740`, `0x1378a0`, `0x137984`, `0x137df8`, `0x26b780`, `0x26b7c4`, `0x26b874`, `0x27cf50`, `0x27cf94`, `0x27d01c`, `0x27d0e0`, `0x290314`. The CDVD/container calls are the three `0x137xxx` sites; other consumers share the UFS service. Data references/function descriptors (including Cobra `0x4530` and dispatcher descriptor `0x73f2c8`) add indirect callers; this is not an exhaustive runtime call graph.

## What a second open would require

**INFERRED:** generic LV1 170/171 and the forwarded read/event/DMA calls can express a second storage lifecycle. The repository routines can enumerate types beyond the fixed HDD selector. A P1 open-only probe needs independently found **LV1** bus/device IDs, its own result/state, and close only after successful open. It should not change the HDD selector, reuse `H`, or call the UFS file-open stub expecting another device.

**INFERRED:** reading later needs a separately validated device DMA mapping, optical region and block size, event/interrupt ownership, independent tag/status state and a real deadline. The HDD's region 1, 512-byte sectors and global cache cannot be assumed for the drive. Linux optical code supplies a public ATAPI command-1 pattern; the stock crypto command-0x88 wrapper does not. Sharing one physical buffer may be possible if explicitly mapped for both devices and serialized, but that is not established here.

**UNKNOWN (console):** optical repository visibility, assignment/ACLs, actual LV1 IDs, whether open succeeds, whether commands/regions are permitted, PS2 DVD/CD sector readability, readiness/authentication behavior and deadline recovery. A CFW hypercall-dispatch patch does not by itself settle device assignment. No P1 payload was built in P0.
